# 10/23 멘토링 후속 조치

[Notion 조사·정리](https://app.notion.com/p/408ec94529fd8180a388fd898b962147?pvs=204)

사용자가 제공한 회의 요약에 따른 우선순위는 crash 먼저, partition 후순위다. 기본 Primary 1 + Backup 2와 결정론적 네트워크 모델을 유지한다. 지표와 함께 실험 조건을 기록한다.

## 이번에 확인한 것

- Java 후보가 없는 것은 아니다. OpenDST·SimGrid·Cassandra simulator의 공식 문서를 확인하고 JDK/API/적용 범위를 비교했다. 설치·실행·A1 연동 PoC는 미수행이다.
- Redis 공식 기본 설정과 튜토리얼 예시를 확인했다. 실운영 환경의 확정값으로 간주하지 않는다.
- Sentinel의 failover quorum/승인과 데이터 쓰기 보존은 구분한다. 상세 근거와 정정은 Notion에 출처와 함께 기록했다.
- 현행 자체 모델은 가상 시각·동일 시각 순서·seed를 고정하고 CSV 재현을 확인했다. 실제 JVM·NIO·파일 I/O 전체를 가상화한 검증은 아니다.

## 다음 질문

목표 환경의 지연·복구 예산, 성공 쓰기 유실 허용, 후순위 Rosé 확장의 마일스톤 포함 여부만 확인한다. 이미 합의된 우선순위나 일반적인 라이브러리 이름을 다시 묻지 않는다.

## 후속 검증

제품 설정 참고 조건의 실험과 외부 시뮬레이터 최소 메시지/crash 재생 PoC는 아직 실행하지 않았다. 기존 502테스트와 실험 결과를 기준선으로 유지한다.
