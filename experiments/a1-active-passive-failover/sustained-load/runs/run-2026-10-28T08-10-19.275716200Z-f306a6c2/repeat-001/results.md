## 해석

- 입력은 응답을 기다리지 않는다. BUSY/실패도 요청 수에서 빼지 않는다. 입력 재시도는 없으며 향후 요청의 경로만 응답에서 갱신한다.
- p50/p99는 제출 구간별 성공 요청만의 정확한 nearest-rank 값이다. 실패는 별도 집계한다. OK/s는 0~30초에 실제 완료한 수 / 30초다.
- summary.csv의 case는 전체 요약, phase는 제출 구간별 결과, sample은 100ms 간격 누적 상태다. phase completedInWindow는 완료 시각 기준이다.
- 따라잡기는 20초의 committed watermark를 노드 2가 적용한 첫 샘플이다. PB는 성공 전에 모두 ACK하므로 성공 watermark 지연은 0이다.
- 정상 시나리오도 같은 3구간으로 나눈다. 새 요청을 30초에 중단한 뒤 최대 30초 추가 관측한다. NO는 관측 상한 내 데이터 수렴 미확인이다.
- 마지막에 모든 성공 키의 값·복사본을 검사한다. TIMEOUT/UNAVAILABLE 요청은 적용 여부가 불확실하므로 존재할 수 있다.
- 실제 서버 처리량이 아니며 동시 처리 1건, 전체 이력 보관, checkpoint 없음이라는 현재 구현 조건의 가상 결과다.
