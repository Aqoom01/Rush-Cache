# A1 EC2 정식 실험 결과 — 2026-11-09

2026-11-09 09:45–11:34 KST, Ubuntu 24.04 ARM64 `m6gd.medium` 3대, Java 21.0.12.1. 정식 250회가 모두 통과했다. 모든 조건을 5회 반복했다. 예비 18회는 정식 집계에서 제외했다.

실행 설정과 원본 JSON·배포본·실행 스크립트의 해시를 검증했다. 각 그룹의 `provenance.json`에는 조건별 원본 해시와 당시 실행한 배포본·스크립트 해시를 보존했다. 각 그룹 종료 시 세 노드의 실험 프로세스가 정리됐음을 확인했다.

## 장애 복구 — 40/40회 통과

요청을 보낸 뒤 응답을 받기 전에 리더를 종료했다. 새 리더의 첫 쓰기 성공과 각 실행의 성공 요청 49건이 생존 노드 두 대에 모두 남아 있는지 확인했다. 총 1,960건, 복사본 3,920개를 검증했다.

| 방식 | 64 B 중앙값 [최소–최대] | 8 KiB 중앙값 [최소–최대] |
|---|---:|---:|
| PB | 498 [471–531] ms | 493 [485–524] ms |
| VR incremental | 550 [547–557] ms | 590 [586–594] ms |
| VR catch-up | 551 [545–556] ms | 589 [586–594] ms |
| Raft | 749 [687–927] ms | 652 [526–771] ms |

VR 두 모드의 관측 범위는 겹쳤다. Raft는 이번 설정에서 복구 시간 편차가 가장 컸다. [집계 CSV](final-results/crash/summary.csv) · [그래프](final-results/crash/crash.png)

## 쓰기 — 120/120회 통과

64 B 1,024건과 8 KiB 128건을 제한된 구간에서 측정하고, 성공한 요청 69,120건을 세 복제본에서 확인했다. 동시 요청 수를 1에서 8로 늘렸을 때 모든 방식에서 실행별 p99 중앙값이 증가했다. 이번 설정에서는 완료 처리량 중앙값도 증가하지 않았다.

8 KiB·클라이언트 8개에서 VR catch-up은 incremental 대비 198.1 → 232.5 ops/s였고, p99 중앙값은 228.83 → 202.64 ms였다. [집계 CSV](final-results/write/summary.csv) · [그래프](final-results/write/write.png)

쓰기 실험은 처음 포트를 점검할 때 이전 TCP 연결의 `TIME_WAIT` 때문에 중단됐다. 리스너가 없음을 확인하고 연결 정리 후 다시 실행했다. 첫 시도는 실제 측정 전에 중단되어 정식 집계에 포함하지 않았다.

## 읽기 — 90/90회 통과

30초 clean read 구간에서 Chain tail 직접, Chain 분산 진입 후 redirect, CRAQ 분산 진입을 비교했다. 90회에서 총 12,842,179건의 읽기가 성공했다.

| 클라이언트 8개 | 64 B 처리량 / p99 | 8 KiB 처리량 / p99 |
|---|---:|---:|
| Chain tail 직접 | 9,253 ops/s / 2.43 ms | 745 ops/s / 24.45 ms |
| Chain 분산 진입 후 redirect | 6,291 ops/s / 3.09 ms | 717 ops/s / 25.28 ms |
| CRAQ 분산 진입 | 13,605 ops/s / 1.89 ms | 763 ops/s / 25.88 ms |

64 B·클라이언트 8개에서 CRAQ 처리량 중앙값은 Chain tail 직접 대비 약 47% 높았다. 8 KiB에서는 약 2.5% 높았고 p99도 1.43 ms 높았다. [집계 CSV](final-results/read/summary.csv) · [그래프](final-results/read/read.png)

## 해석 범위

- 장애 시점은 클라이언트가 요청을 보낸 뒤 응답을 받기 전이다. 서버 내부의 특정 commit 지점을 지정한 실험은 아니다.
- 쓰기 처리량은 재시도 비용을 포함한 짧은 구간의 완료 처리량이다. p99는 실행별 값의 중앙값이며, 그래프 범위는 다섯 실행의 최솟값과 최댓값이다.
- 읽기에는 동시 쓰기가 없다. 부하 발생기와 노드 프로세스가 한 서버의 1 vCPU를 공유한다.
