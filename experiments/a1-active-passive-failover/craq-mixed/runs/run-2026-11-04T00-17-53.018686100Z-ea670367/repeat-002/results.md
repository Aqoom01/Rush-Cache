# CRAQ 혼합 부하 결과

조건 288개, 읽기 성공 365360, 쓰기 성공 21928, 쓰기 BUSY 44712, 읽기 구간 검증 위반 0.

- 고정 3노드, 1MiB/s, 전파 1ms. 정상 상태 입력 3초, 2ms마다 1건(1500건), 요청 deadline 1000ms, 입력 후 최대 10초 drain. 재시도 없음.
- 쓰기 비율 0/1/5/10/25/50%, key 수 1/64, 값 64/8192B, tail Ack/Completed 추가 지연 0/20ms, seed 1/2/3. quick은 0/10/50%,8192B,seed1.
- 같은 seed/설정은 두 모드에 동일한 연산·key·값·도착 시각을 준다. CRAQ는 읽기를 순환 배치, Chain은 tail 배치.
- 쓰기는 기존 단일 in-flight 엔진이다. 설정한 쓰기 비율은 제출 비율이며 실제 성공 비율과 다르다. 성공/BUSY/TIMEOUT/기타를 함께 보고한다.
- key별 실제 tail KV 적용 이벤트와 GET 제출/응답의 전체 순서를 대조한다. 각 GET 값이 요청 시작 당시 또는 요청 중 확정된 값인지 확인한다. 다중 key transaction 검증은 아니다.
- warmup 제외, drain 포함 peer 비용. CPU·client 링크·값 응답 비용·GC·디스크 없음. 모델 p99/로컬 0ns를 실제 지연·처리량으로 주장하지 않는다.
- 운영 지연 예산·쓰기 보존 요구와 실 서버 검증은 후속이며 이 탐색 실험으로 멘토의 결정을 대신하지 않는다.
