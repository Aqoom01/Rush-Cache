## 핵심 결과

- SC1에서 N=10,000/100,000/1,000,000의 쓰기 차단은 25/234/2,322 tick이다. 고정 전송 예산에서 데이터 크기에 따라 쓰기 차단이 증가했다.
- SC1의 N=100,000에서 예산 16/64/256 KiB/tick의 쓰기 차단은 930/234/60 tick이다. 15/15회가 예측식 `ceil(보낸 바이트 / 예산) + 1`과 일치했다.
- SC2의 rho=0.00/0.10/0.50에서 쓰기 차단은 모두 234 tick, 거절 수는 0/10,089/50,445건이다. 이 모델에서는 rho가 거절 수를 바꾸고 쓰기 차단 시간은 바꾸지 않았다.
- 26개 조건 × seed 1, 2, 3, 4, 5: 총 130회 실행, 정합성 규칙 위반 0건. source/destination 전체 데이터 비교 260/260건 일치. 결과: 완료 75회, 취소(요청) 15회, 취소 거부 10회, 취소(timeout) 30회. `취소 거부`도 이동은 완료됐다.
- SC5의 timeout 시 쓰기 차단은 55 tick, 같은 크기 정상 이동은 25 tick이다. 실패 후 freeze 해제까지의 가용성 비용도 포함한다.

전송량·전송 예산에 따른 virtual tick 모델의 결과다. 실제 서버의 초 단위 downtime·latency 또는 네트워크 성능으로 환산하지 않는다.

모든 조건에서 seed별 지표와 결과가 같다. 표는 조건당 한 행으로 모았다. 고정 record 크기·전송 예산·이상 주입 시점과 credit 기반 요청 수, freeze 중 쓰기 거절 때문에 seed는 key 선택과 내용을 바꾸지만 집계값은 바꾸지 않는다. 반복 실행은 입력별 정합성 확인이며 성능 분산·신뢰구간 추정용 표본이 아니다.
